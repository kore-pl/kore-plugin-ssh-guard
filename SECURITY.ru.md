# Раскрытие уязвимостей безопасности

Этот файл описывает процесс раскрытия уязвимостей для данного репозитория плагина (id `ssh-guard`); это не документ по проектированию безопасности.

## Область применения

Охватывает: реализацию `SSH 加固插件` (id `ssh-guard`), объявление возможностей в `info.json`, фронтенд `web/` и артефакты `make dist`.

Не охватывает: проблемы ядра и протокола — сообщите о них согласно [SECURITY.md проекта kore](https://github.com/kore-pl/kore/blob/main/SECURITY.md); известные уязвимости внешних зависимостей также следует сообщать вышестоящему проекту.

## Поддерживаемые версии

| Версия | Статус | Примечание |
| --- | --- | --- |
| `0.4.0` (последняя) | ✅ Принимается и исправляется | Исправления безопасности предоставляются только для последнего патча |
| Более старые `0.x` | ❌ Не поддерживаются | Сначала обновитесь до последней версии |

На стадии `0.x` поддержка минимальна: исправления получает только последний патч ветки minor; старые патчи не портируются.

## Поверхность атак репозитория

- **RPC-методы**: все методы `ssh-guard.*` (см. `README.md`); отсутствие проверки параметров может привести к повышению привилегий или внедрению.
- **capabilities**: `info.json.capabilities` — полная поверхность авторизации плагина; каждое лишнее объявление — ещё один вектор атаки.
- **Отдельный процесс и UDS**: плагин работает отдельным процессом; сокет создаётся хост-оболочкой, `chown kore-<id>`, режим `0600`; обход прав сокета или подключение к сокету другого плагина является уязвимостью.
- **Поверхность записи в хост**: записи вне фактически выданных capabilities (файлы / процессы / сеть / база данных) являются уязвимостями.
- **Фронтенд**: `web/` работает в iframe с отдельным origin и взаимодействует с хост-оболочкой через postMessage; XSS, подделка сообщений и чтение данных других плагинов — проблемы границы безопасности.

## Как сообщить

1. **Предпочтительно GitHub Security Advisory**: страница Security этого репозитория → "Report a vulnerability" (закрытый канал, без публичного issue).
2. **Резервная почта**: `pengtang1024@users.noreply.github.com`, тема `[kore security] ssh-guard`.
3. **Не открывайте публичные issue и не публикуйте PoC в обсуждениях или PR.**
4. Укажите: затронутую версию, шаги воспроизведения или PoC, оценку влияния, известность проблеме и пожелания по кредиту.

## Сроки и раскрытие

- Подтвердите получение и дайте первую оценку в течение **72 часов**; сложные случаи получают план позже.
- Координируйте раскрытие после исправления, со стандартным окном **90 дней**; при активной эксплуатации сначала проконсультируйтесь.
- Зафиксируйте исправления безопасности в `CHANGELOG.md` после релиза (без деталей эксплуатации) и при необходимости опубликуйте предупреждение о безопасности.
